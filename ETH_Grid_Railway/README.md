# ETH/USDT на Railway
Реальные сделки. При первом запуске с пустой базой бот выделяет 100 USDT и отправляет первую заявку примерно на 10 USDT.

1. Остановите Windows-бота Ctrl+C. Для работающего реального бота сохраните его eth_live.sqlite. Если остановка была во время сделки, при переносе бот продолжит сверку с биржей по ID заявки.
2. Загрузите Dockerfile и eth_live.py в отдельный GitHub-репозиторий и подключите его как сервис Railway. Программа запускается командой из Dockerfile. Используйте одну реплику, выключите Serverless, подключите Volume с путём /data.
3. Если на ПК уже запускался реальный бот, **до добавления ключей** перенесите базу в корень нового Volume. В PowerShell из папки старого бота с Railway CLI, после railway login и railway link (выберите нужный проект), выполните:
   
       railway volume files upload ./eth_live.sqlite /eth_live.sqlite

   Выберите Volume бота. В контейнере файл появится как /data/eth_live.sqlite. Сохраните резервную копию. Если старая база утеряна после реальных сделок, сначала сверьте историю и восстановите состояние. Если запускалась только симуляция, начните с пустого Volume.
4. Railway → Variables: BYBIT_API_KEY, BYBIT_API_SECRET, BYBIT_REGION (kz или com). Используйте ключ спотовой торговли без вывода. Применение переменных запускает торговлю. Если у ключа ограничение IP, разрешите статический исходящий IP сервиса Railway. Не помещайте ключи и базу в GitHub.
5. В Deploy Logs появятся бюджет и «Бот работает | ETH/USDT». Если видите остановку, прочитайте строку причины. В Settings → Restart Policy включите Always на поддерживаемом тарифе. Следите за остатком бюджета хостинга.
6. Для команд на сервере откройте railway ssh в связанном сервисе. Используйте python /app/eth_live.py status. Для добавления бюджета после перевода средств на единый торговый аккаунт: python /app/eth_live.py deposit 50. Бот продолжает работать во время пополнения.
7. Не запускайте локальную торговую копию с тем же счётом. На одном Volume процесс защищён блокировкой. Если связь оборвалась при отправке ордера, процесс при рестарте ищет его по ID. Длительное «Ожидание сверки заявки» требует проверки этого ID на Bybit. Удаление базы может привести к повторной покупке.
